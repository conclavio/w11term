# Linux PTY recovery trial

The Windows workspace keeps the layout. On Linux, zmx 1.0.1 can keep the foreground editor running and reconstruct its alternate screen when the attaching client disappears. The isolated PTY test recovered the original Vim process and unsaved buffer at 107 × 33 cells. Its first new keystroke stayed in insert mode. The capture contained no replay of the earlier clipboard write, notification, sound request or standalone bell. The application had to redraw its static kitty image. [Linux run](https://github.com/conclavio/w11term/actions/runs/44789901404)

An ordinary `zmx attach NAME` creates a session if it cannot find one. The client needs a random name and a generation label bound to the verified host and user. Check that label before resuming and again before accepting input. Supplying `/bin/false` as the fallback command on resume prevents an expiry race from silently creating an interactive replacement shell. Each remote session has its own generation. [zmx usage](https://zmx.sh/getting-started)

Run `sh tests/durable/run-linux.sh` on Linux with Vim and Python 3. The test uses a temporary home and socket directory. After detaching it discovers the PTY by listing that account's sessions, checks the generation and resumes the editor. The separately hosted Windows tests exercise the SSH transport and GUI.

Host discovery probes zmx and tmux independently over the selected account’s authenticated SSH transport. w11term reads the tab-separated `zmx list` fields, matches its generated name and generation label, and skips ended or unreachable sessions. The command and directory are display text. The selected reference uses the verified SSH fingerprint and the profile's endpoint and username. The zmx attach path checks the generation again before and after opening the PTY. This works across Windows clients that can log in to the same Linux account and see the same zmx socket directory. [zmx 1.0.1 listing format](https://github.com/neurosnap/zmx/blob/v1.0.1/src/util.zig)

For stock tmux, a read-only `list-sessions` command on the default socket returns names, window counts, attached-client counts, stable session IDs, the server PID and session creation time. After selection the client requests a real SSH PTY. A tmux format condition checks the server, creation time and ID before running `attach-session` in that same server. w11term waits for its new client PID to appear on that session before it accepts input. The same checks apply on reconnect and workspace restore. tmux manages its windows and panes inside the attachment. Its other clients stay attached. [tmux clients and sessions](https://man.openbsd.org/tmux#CLIENTS_AND_SESSIONS)
