# Native workspaces and durable SSH sessions for w11term

**Proposed design · 20 November 2026 · w11term baseline `001cddb`**

A Windows user should be able to put a remote editor beside a build log, open a file drawer for either host, and add a local PowerShell pane to the same workspace. On a Linux host with session persistence enabled, reopening the workspace should also return the user to the editor or build that was already running. Windows owns layout, input and rendering. Native SSH profiles connect directly through russh. ConPTY provides a separate path for launching local console programs.

## Ship order

| Release | User-visible result | Remote requirement |
| --- | --- | --- |
| 1. Native splits and named workspaces | Split, focus, resize or zoom a pane and reopen a saved layout. | Ordinary SSH. Panes may connect to different hosts. |
| 2. SFTP drawer and SSH profiles | Browse and transfer files beside a terminal, reuse SSH aliases and connect through a jump host. | The existing SSH connection and the host’s SFTP subsystem for file operations. |
| 3. Optional durable Linux sessions | Return to the same running program after network loss, Windows sleep or a w11term restart, including from a fresh workspace. | zmx owns each PTY and lists its sessions for the authenticated Linux account. |
| 4. Terminal fidelity and Windows accessibility | Compose text with a Windows IME, read terminal content with Narrator, and render a wider range of text and graphics correctly. | Applicable to every terminal pane. |
| 5. Local PowerShell via ConPTY | Open a Windows shell beside a remote session from the same profile picker. | Runs entirely on Windows. |

RustMUSH cockpit reattachment follows the general-purpose roadmap. A Windows machine and an ordinary Linux SSH host suffice to exercise all five releases.

The [Windows folder sharing roadmap](#mount-selected-windows-folders-on-a-linux-ssh-host) covers read-only mounts and per-folder write access.

The [SSH host groups roadmap](#ssh-host-groups) covers running the same command across live remote shells from a single Windows tab.

## Current capabilities

Each terminal tab has its own session, scrollback, search state and programmable control surface. Scripts can target a background session by ID, write raw bytes, wait for a regex, read committed screen text, capture PNGs and record VT output. The same authenticated SSH connection also supports SFTP. Profiles already support creation, editing and renaming, plus key, agent, password and keyboard-interactive authentication. [Current features](../README.md#tabs-and-profiles) · [Control and SFTP API](../CONTROL.md)

Today the pane registry publishes each terminal tab’s ID, and the UI watches frames from the selected tab. Reconnect opens a fresh SSH session and remote PTY. Window placement and local scrollback can survive events that end the remote foreground program. The renderer supports synchronized text and image updates, static kitty image replacement and sixel. Animated images display their first frame. The existing image audit covers replacement, deletion and resize. The loopback typing measurements cover a different workload from graphics or split-pane rendering. [Pane registry and frame watcher](../src/app.rs) · [SSH transport](../src/ssh/transport.rs) · [Graphics audit](graphics-audit.md) · [Benchmark scope](../bench/README.md)

## Release 1 · Native splits and named workspaces

Give each terminal a process-local pane ID that remains stable when the pane moves, changes focus or is zoomed. A terminal tab owns a layout tree. Its leaves refer to panes and its branches store a horizontal or vertical split and divider proportion. A workspace saves the tab order, tree, profile references and focused leaf. On reopen, each leaf gets a fresh local ID. A durable remote session reference, when present, identifies what that leaf should reattach to.

Each visible pane needs its own grid, frame subscription, selection and pointer coordinates. Keyboard input goes to the focused pane. Release held keys on the old pane when focus moves. Zoom temporarily gives one leaf the full tab and restores the previous proportions on exit. Hiding a pane leaves its SSH session running. **Split current host** can request another channel on the same authenticated connection when the endpoint, identity and trust settings match and the server permits it. Keep **Open profile** as an independent login and allow a split to use a different profile.

Preserve the existing control API’s meaning of `--pane`. Keep one focused terminal marked `active` and expose tab membership and visibility separately. Retain the current single-pane resize behavior. For a visible split, adjust the layout to satisfy the requested cell grid or return a clear geometry error. File transfers, screenshots and raw writes directed at another pane must leave focus where the user put it. [Current control contract](../CONTROL.md#waiting-geometry-tabs-and-events)

**Search the window’s tabs.** Find terminal and utility tabs by their current display title or tab position, including tabs beyond the visible strip. Switch to the tab’s remembered pane and keep Escape available to dismiss the search.

**Acceptance.** Open two loopback terminals with distinct output. Move the divider, zoom and restore a pane, and continue addressing both original IDs from the CLI. Verify each reported grid and PNG, keyboard input on the focused side, and uninterrupted output on the other. Reopen the saved workspace and check its profiles, proportions and focus.

## Release 2 · SFTP drawer and SSH profiles

Open the drawer for a specific pane and show the host and remote directory above the file list. Start with browse, upload, download, drag-and-drop and transfer progress. Use the existing SFTP worker and overwrite policy. Bind each transfer to its original pane even if the user changes tabs or focus. Use the SFTP working directory by default. Following the shell’s current directory is a separate feature and needs a remote directory report. [SFTP semantics](../CONTROL.md#sftp)

Add duplicate and delete to the profile editor. Import common OpenSSH host settings and support `ProxyJump` with host-key verification for each hop. Show users which settings were imported and flag unsupported directives. [OpenSSH configuration](https://man.openbsd.org/ssh_config)

**Acceptance.** Transfer a file while typing into another pane and verify the bytes at the destination. Exercise an overwrite refusal, a disconnect during upload and a server that declines SFTP. The drawer should report the outcome, including a possibly partial upload, and the terminal should remain usable when only SFTP fails. Connect through a test jump host and verify the destination’s host key independently.

## Release 3 · Durable Linux sessions

There are three separate recovery promises. A **saved workspace** can reopen the same profiles and geometry. **SSH reconnection** can establish a fresh login after the network returns. **Durable attachment** returns to the original shell, working directory and foreground process because a process on the Linux host kept the PTY alive. A background service on Windows could keep a connection open after the GUI exits, but it cannot provide target-side durability during a network outage.

| --- | --- |
| Eternal Terminal | SSH bootstraps a separate encrypted TCP transport. The peers track sequence numbers and catch up missed bytes after reconnecting. ET 7.1 also supports named sessions. It is the reference for recovering from a Wi-Fi change mid-command. [Protocol](https://github.com/MisterTea/EternalTerminal/blob/master/docs/protocol.md) · [7.1 release](https://github.com/MisterTea/EternalTerminal/releases/tag/et-v7.1.0) |
| zmx | A host-side process owns each named PTY, forwards live bytes and maintains a terminal model for reattachment. It leaves the layout to Windows. **First trial** for one durable shell per native pane over ordinary SSH. [Architecture](https://zmx.sh/architecture) · [SSH workflow](https://zmx.sh/ssh) |
| Herdr Core | Explicitly browse and attach existing Linux terminals through `hc connect` over native SSH. The Windows viewer renders the screen, forwards input and resizes, and verifies the selected Core, terminal and process on reattach. [Versioned attach protocol](https://github.com/herdrdev/herdr-core/blob/v0.1.21/schema/README.md#attach-streams) |
| Zellij | Version 0.46 exposes a Rust library for building a Zellij distribution with bundled configuration, layouts and plugins. The documented entry point runs that application. | tmux control mode | Exposes pane output, IDs and layout changes to external clients. The strongest reason to build an adapter is to open sessions users already run in tmux. [Control mode](https://github.com/tmux/tmux/wiki/Control-Mode) |
| Venti | Venti 0.2.0 selects graphics by terminal name. With w11term’s SSH defaults (`TERM=xterm-256color`, `COLORTERM=truecolor`), Venti selects no graphics. For Sixel forwarding, choose `xterm-sixel` under **SSH terminal type (TERM)** in the profile editor and open a new session. Enable `general.graphics = true` in Venti. The Linux mux CI job runs the [stock Zellij 0.46.0](https://github.com/zellij-org/zellij/releases/tag/v0.46.0) and [Venti 0.2.0](https://github.com/programmersd21/venti/releases/tag/v0.2.0) binaries behind a temporary loopback SSH server. An alternate-screen application inside each mux receives a typed character, a resize from 100 × 30 to 126 × 38, and a right-arrow key. The Venti fixture draws a red Sixel beside a text label and redraws it at the new pane center on resize. Windows CI replays the captured bytes through w11term’s terminal engine and checks the label, image cell, color and absence of a stale placement. It also compares every query reply the SSH peer received with the bytes w11term itself generates, including the Zellij Kitty and synchronized-output probes. The default Venti run checks text and suppression of graphics. Zellij runs with the stock distribution and a single test pane.

To reproduce on x86-64 Linux with OpenSSH client/server, sudo, Bash and Python 3.11 or later, run `bash tests/durable/run-mux-linux.sh artifacts`. Copy the capture directory to Windows, set `$env:W11_MUX_CAPTURES` to its path, and run `cargo test --locked --test remote_mux -- --ignored`.

Make durability opt-in per profile. Distinguish **Detach**, **Reattach** and **End remote session**. Scope the saved remote reference to its host and user. If the helper is unavailable or the saved session has expired, report that and offer **Start new shell**. Some attach commands also create a session when the name is missing. The trial must detect that case before reporting successful recovery. SFTP can reopen on the new SSH connection independently of the shell.

**Decision test.** Start an editor with an unsaved buffer and record the remote shell PID. Drop the transport, reconnect, then restart w11term and repeat. Verify the PID, buffer, current grid and first keystroke. Repeat with an alternate-screen TUI and a static image. Reconstructing a display must avoid replaying old clipboard writes, bells, sounds or user input. Use these results to choose a backend and document exactly what it restores.

## Release 5 · Local PowerShell via ConPTY

Add **Local PowerShell** to the same **+** and split menus as SSH profiles. A local profile identifies a Windows executable, its arguments and an optional starting directory. Offer PowerShell 7 (`pwsh.exe`) when installed and Windows PowerShell (`powershell.exe`) under its own label. A saved workspace records which executable to launch. Reopening it starts a fresh local process.

Choose the backend when opening the pane. An SSH pane exchanges terminal bytes directly with its russh channel, preserving the existing path for kitty graphics, keyboard negotiation and raw control writes. A local pane launches its child attached to a Windows pseudoconsole. w11term reads ConPTY’s output pipe into the same VT engine and renderer, writes terminal input to its input pipe, and passes cell-grid changes to `ResizePseudoConsole`. Only local sessions incur ConPTY’s translation and I/O costs. Keep SFTP and remote reattachment scoped to SSH panes. [Windows pseudoconsole lifecycle](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session) · [Grid resizing](https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole)

**Acceptance.** Split a live SSH tab and select **Local PowerShell**. Verify that typing, Ctrl+C, resize and exit reach the intended pane, and that closing the local shell cleans up its child and pipe handles while the SSH session continues. Drive the remote pane through the CLI during local output and compare its received bytes and captured image with the direct-SSH fixture. Restore the layout and verify the local pane opens in its configured directory.

## Mount selected Windows folders on a Linux SSH host

A saved SSH profile can mount selected NTFS directories through stock Linux SSHFS. Read-only is the default. Each writable folder requires an explicit choice in the Windows picker. Linux can create and edit files, rename entries, and remove files or empty directories. A real Linux guest exercises both access modes and holds a descriptor across transport loss and reconnection. [Folder sharing](../README.md#share-a-windows-folder-with-linux)

Let an SSH profile share one or more folders chosen with the Windows folder picker. For example, the profile could mount `C:\Projects\sprites` at `~/windows/sprites` when it connects. A Linux editor or build can then use ordinary filesystem paths. Show each share’s host, mount point, access mode and mount status in w11term, with an **Unmount** action. Sharing starts disabled. Each folder defaults to read-only, with write access granted separately per folder.

Use a separate SSH exec channel on the authenticated connection, without a PTY. Linux runs SSHFS in its documented `-o passive` mode, which carries SFTP requests on standard input and output. w11term serves those requests from a Windows directory handle scoped to the selected folder. FUSE supplies the Linux mount. This design requires SSHFS, permission to use FUSE and permission to run the mount command on the host. It needs neither a Windows filesystem driver nor an inbound listener. If the mount fails, show the reason and keep the shell usable. [SSHFS manual, passive mode](https://github.com/libfuse/sshfs/blob/ba33bab77006cfb81cbd6ecc44a8fc2728d24793/sshfs.rst#L150-L154)

Bind each share to the verified host and SSH account. Refuse drive roots and use a user-owned, empty Linux mount point with SSHFS’s default owner-only access. Programs running as that Linux user can access the mount. Enforce read-only mode and containment on Windows for every operation, including rename and link handling. Path traversal, Windows device paths, alternate data streams and junctions must never give the remote host access outside the selected tree. On unmount or connection loss, close the export and invalidate its handles. A reconnect may remount configured folders after host verification. An interrupted write must surface an error and must never be silently replayed.

**Acceptance.** Mount a temporary Windows folder on a real Linux FUSE host. Read a file through the mount, verify that a sibling folder stays inaccessible even through a junction, and verify that read-only mode rejects changes. Enable writes for that folder and exercise create, rename and delete from Linux. Drop the SSH connection during I/O, reconnect, and check that old handles fail, the configured share remounts and the terminal still accepts input. Also exercise explicit unmount and a host without SSHFS.

## SSH host groups

Polysh keeps an interactive SSH shell on each host. Its prompt summarizes which shells are ready, its roster lets the operator add hosts and change the active set, and its output identifies the originating host. Each shell keeps its working directory and environment across commands. [Polysh prompt, output and host controls](https://github.com/innogames/polysh#prompt)

Add a native **SSH host group** tab. Start with live SSH panes across the current window and use their profile and `user@host:port` to identify each target. Give the group a single-line command field, a checkbox per target and an explicit **Send to _n_ hosts** action. Keep each terminal independently focusable for authentication, interactive applications and host-specific follow-up. The command field sends on submission, and each pane retains its own shell and scrollback.

1. **Select and send.** Show connection and prompt state separately. Use observed OSC 133 or OSC 633 shell markers for prompt readiness and command completion. A fresh input marker gives the pane a prompt token. Manual input or group submission consumes it, so a partially edited line cannot receive a second command. In the session worker, recheck the token and connection generation along with read-only, authentication and alternate-screen state. Carry the generation through the SSH write queue so late writes cannot enter a replacement channel. Show **Prompt unverified** until a fresh prompt is detected and report rejects by host.
2. **Follow results.** Keep a bounded, host-labeled command view in the group tab. Show delivery, running, completion and exit status independently. Summarize progress across all recipients and filter visible results by outcome. Treat successful delivery to the SSH channel as separate from remote command completion. Use existing command history for marked output and link each result to its original terminal. Copy the viewed submission as a plain-text report with all host statuses and the available output. Load a previous or saved command for review and save reusable drafts to the shared command library. A slow or disconnected host leaves the other shells usable.
3. **Recall and extend groups.** Save named groups by SSH profile, including from the visible roster selection, and open their shells together from the group tab or command palette. Add and pause individual members during a session. Filter the roster by profile, pane name or address and change the visible selection in bulk. Show readiness for the current selection and let the operator select only the ready hosts shown. Scope sends and interrupts to selected hosts shown in the roster, and require verified running state for interrupts. Offer an optional per-profile prompt matcher for equipment shells that lack shell integration. Reuse the existing native SSH transport, host verification and authentication for every member.
4. **Show interleaved output.** Follow verified shell output in a single newest-first view during a submission. Label each line by host, bound retention, and show gaps. Pause the view without pausing the shells and focus the originating pane from a line. The per-pane command history retains the full transcript while its capture is available.
5. **Bring in host lists.** Paste profile names, hosts, or SSH addresses and expand a numeric hostname range. Resolve unambiguous saved profiles, report duplicates and ambiguous entries, and open checked targets only after a preview. Revalidate the reviewed profile matches before connecting. One-time addresses use the supplied default user when needed and the existing SSH authentication and host-key flows.
6. **Recover exited hosts.** Reconnect a single shown host or the checked hosts shown by the roster filter once their previous sessions have ended. Reuse the existing pane and scrollback. A fresh SSH login requires a new verified prompt, and previous submissions remain available for review.
7. **Prepare retries from results.** Load the original command for review and select visible original recipients with a confirmed nonzero exit or withheld delivery. Keep the previous draft and roster scope restorable. Require an explicit send and recheck each recipient’s current prompt.
8. **Set up prompts from the roster.** Offer the bundled shell integrations and a pane-local appliance prompt regex. Keep changes through reconnects in that pane. Invalidate fallback readiness and wait for a newly printed match when the regex changes.
9. **Upload one file to selected hosts.** Review one local file, a full remote file path, and the checked hosts shown in the roster. Bind each upload to the reviewed SSH connection and use exclusive SFTP creates to preserve existing files. Limit concurrent transfers and report each host’s progress and final result. Let the operator cancel outstanding transfers.
10. **Target by wildcard.** Let operators switch the roster filter to whole-name, case-insensitive patterns. Combine name, profile, hostname and SSH address patterns with explicit exclusions. Preserve hidden checks and scope recipient actions to the visible roster. An invalid pattern yields an empty scope until corrected.
11. **Save a submission report.** Export the viewed run as UTF-8 with every host outcome and its retained command output. Capture the report when the operator opens the Save dialog and write it atomically at the confirmed destination.
12. **Collect one file from selected hosts.** Download an explicit remote path into a fresh local folder. Use pane-specific filenames and the reviewed SSH connection for each fetch. Publish complete files as they finish, preserve existing files, and report failures and cancellations per host.
13. **Compare submission results.** Group hosts by verified exit code and full captured output. Show small groups first, identify the first different line relative to the largest group, and link each result to its retained command history. List pending hosts and incomplete captures separately. Refresh the comparison on request.
14. **Keep multiple groups open.** Open saved groups in dedicated tabs with separate drafts, rosters and results. Scope each named roster to its launched and imported panes, with an explicit window-wide view. Keep an independent window-wide roster available for ad hoc groups and return to the most recent group from its terminal.
15. **Edit live roster membership.** Review existing SSH panes in the window and add or remove them from a named tab. Keep membership separate from the send selection, retain command drafts and results, and revalidate panes at apply time.
16. **Reuse live connections when opening a saved group.** Review one connection choice per profile and open new panes for the remaining profiles. Suggest a unique matching pane and let the operator choose among duplicates. Revalidate saved profiles and approved SSH generations before opening the named tab.
17. **Update a saved group from its live roster.** Review profile additions and removals for the named tab's original group. Deduplicate profiles, preserve their saved order, and explain unavailable panes. Require a fresh review when the roster changes and protect saved group edits made elsewhere.
18. **Reuse named recipient selections.** Save checked, shown profiles as a recipient set within their named group. Apply a set to the same live shells when each profile resolves to exactly one roster pane. Keep a missing or ambiguous set from changing the current selection, and keep applying a set separate from sending a command.
19. **Apply recipient sets from the keyboard.** Search the command palette for a set in the current named group and press Enter to apply it. Validate the same saved definition and live roster before changing the checked panes.

## Subsequent features for RustMUSH

**Resume the cockpit through the game gateway.** The port-22 `sshdoorway` terminates the player’s SSH connection and opens a separate upstream SSH connection to the instance. Its current teardown closes the upstream channel when the player drops. That is what lets the game apply linkdead rules. The per-instance gateway owns the SSH TUI and can also serve players who connect directly on 6789 or 6792. Use the doorway to forward an authenticated resume request and let the instance restore the character and view. This also allows a reconnect to arrive through a different doorway generation.
